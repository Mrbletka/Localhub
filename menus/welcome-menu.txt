1. WHAT THIS MENU IS
--------------------------------------------------------------
This is not a popup. It is the MAIN MENU of the Colony Simulator:
the front door of the game.

  - It is the first thing every player sees after joining.
  - It is the HUB every other menu starts from and returns to.
  - It reopens anytime with the Colony Ledger item.

If a player only ever learns one screen, it is this one.


2. DESIGN GOALS
--------------------------------------------------------------
  1. ONE OBVIOUS NEXT STEP
     Every screen has exactly one green primary button, focused
     by default. Pressing Enter / A / tap always does the
     sensible thing.

  2. READ THE COLONY IN 3 SECONDS
     A returning player knows "is everything OK?" at a glance:
     4 stats, 3 events, 1 request. Details live one click deeper.

  3. FEELS LIKE MINECRAFT, LOOKS PREMIUM
     Pixel icons, blocky frames, Minecraft font, but with a
     clear layout, consistent spacing and a real colour system.

  4. WORKS ON EVERY DEVICE
     Touch (phone/tablet), controller (console) and mouse +
     keyboard (PC) are all first class. See section 9.

  5. NEVER IN THE WAY
     It opens fast and closes in one press. Returning players
     with nothing new can skip it entirely (section 11).

  6. THE COLONY FEELS ALIVE
     News, deltas, and a colonist asking for help. The world
     kept going while you were away.


3. HOW IT IS BUILT IN BEDROCK (FEASIBILITY)
--------------------------------------------------------------
Two layers, so the menu can never break:

  LAYER 1: Plain ActionForm (the FALLBACK)  -> _fallback.png
    The standard Bedrock button menu. Always works, on every
    device, after every Minecraft update. Built first.

  LAYER 2: Custom skin (the FULL DESIGN)    -> _first-join.png,
                                               _returning.png
    A resource-pack JSON UI skin applied to that same
    ActionForm. A hidden tag in the form title tells the skin
    "draw this one as the Main Menu". Many Marketplace add-ons
    use this technique.

  THE RULE: both layers show the same buttons, in the same order,
  with the same text. The skin only changes the LOOK. If an update
  breaks the skin, players get the fallback and nothing else breaks.

  Limits to design around:
    - Everything dynamic (stats, events, names) reaches the screen
      as TEXT. Data must be short, pre-formatted strings.
    - Display-only pieces (stat tiles, feed items) travel as extra
      tagged text or non-clickable "buttons" that the skin places.
      !! Needs a small technical prototype (a "spike") before we
         commit to the full layout. Track in tech/json-ui-spike.txt.
    - Icons are texture files in the resource pack (16x16).
    - Real-time animation is limited; simple fades and slides are OK.

                  1 colonist request, link to Chronicle

    Overview · Chronicle · Alerts · Guide · Settings
    Badges: gold = new things to read, red = needs action.
    Alerts tile with 0 alerts: no badge, still shown (stable layout).

  "Next milestone" = the colony's next growth goal
  (Camp > Hamlet > Village > Town > City). It gives every session
  a reason to keep going. -> systems/progression.txt (planned)

6. OTHER VARIANTS
--------------------------------------------------------------
  C) RETURNING MEMBER   same as B, but:
       - title role is their own, e.g. "Steward Alex"
       - stats they can't see are shown as "Ask the Governor"
       - no colony-admin actions
  D) WANDERER           no colony (left, exiled, or colony fell)
       - layout like A, cards: "Found a New Colony" / "Join"
       - if their colony fell: a third, smaller card
         "The Fall of Oakvale: read its Chronicle"
  +  ADMIN EXTRA         ops/host get a 6th nav tile: World Admin
                        (crown icon) -> menus/world-admin.txt


7. COMPONENTS  (-> _ui-kit.png)
--------------------------------------------------------------
  Every future menu reuses these. Nothing new without a reason.

  Primary button   green, only 1 per screen, big label + subline
  Secondary button dark grey, same shape as primary
  Ghost button     small, icon + text, for side actions
  Nav tile         square, icon + label, optional badge
  Badge            red (urgent) or gold (new), top-right corner
  Pill / chip      small info labels (time away, day, player)
  Stat tile        label + value + coloured bar
  Feed item        coloured edge + icon + text + time + symbol
  Request card     dashed gold frame, colonist face + quote
  Colony crest     banner shape, colony colour + emblem
  Choice card      pixel scene + title + body + button (first join)
  Close button     [X] top-right, always in the same place

  States for every clickable part:
    default · hover (mouse) · focus (controller/keyboard) ·
    pressed · disabled


8. VISUAL STYLE
--------------------------------------------------------------
  Colours
    Panel       #1C1E23    Raised      #2C3038    Frame   #0A0B0D
    Text        #F3EFE6    Muted       #A8A397
    Gold        #F2B84B    brand, focus ring, "new", highlights

    Good        #6CC35A    Neutral     #E8C547
    Bad         #E5554F    Info        #5BB4E5

  Type (Minecraft font in-game, the mockups use a look-alike)
    Display 44 · Title 32 · Heading 26 · Body 15-17 · Caption 13
    Eyebrow 12, UPPERCASE, wide letter spacing

  Frames
    2px near-black border, 1px light top edge, darker bottom edge.
    It's the classic Minecraft "bevel", flattened and modern.

  Backdrop
    The live world stays visible behind the menu, darkened
    with a vignette. You never feel teleported out of the game.

  Icons
    16x16 pixel art, 2-3 colours each, readable at 18px.
    Current set: flag people book compass arrow hall scroll bell
    gear heart bread shield person sun crown head house tree
    -> assets/icons.txt (planned)


9. INTERACTION & DEVICES
--------------------------------------------------------------
  Default focus   the primary button (CONTINUE / START)
  Controller      D-pad/stick moves focus in reading order:
                  top bar > left column > right column > nav row
                  A = select · B = close · gold focus ring
  Keyboard        Enter = select · Esc = close · arrows/Tab move
  Touch           every target at least 48px tall, no hover-only
                  info. Control hints in the footer are hidden.
  Mouse           hover state on everything clickable

  Open / close    150 ms fade + small slide up. A soft "page turn"
                  sound on open, a click on select.
  Small screens   phones: stats become a single row of 4,
                  the news card shows 2 events instead of 3.
                  (Mockup for phone layout: TODO)


10. CONTENT RULES
--------------------------------------------------------------
  Voice      warm, short, a little storybook. Talk TO the player
             ("Welcome back, Governor"), never like a system log.
  Lengths    colony name max 16 chars · event line max 40 chars ·
             request max 60 chars · button label max 18 chars
  Numbers    whole numbers, units always shown ("6 days", "14/20")
  Status     always colour + symbol + word: "+", "~", "!"
             (colour-blind safe, readable in the fallback too)
  Events     pick max 3: most important first, then newest.
             Deaths and attacks always beat births and trade.
  Localize   all text from language files. Leave ~30% extra room,
             because German and Portuguese run long.


11. WHEN IT SHOWS  (TRIGGERS)
--------------------------------------------------------------
  [x] On first spawn after joining the world.
  [ ] NOT on respawn after death, NOT on dimension change.
  Re-open: Colony Ledger item, or /scriptevent colony:menu

  Bedrock catch: a form opened while the player is still loading
  gets cancelled ("UserBusy"). Retry every second, max 30 seconds.

  Player setting "Main menu on join":
    Always
    Only when something happened   <- default for returning players
    Never
  When skipped, show an ACTION BAR MESSAGE instead (one line of
  text above the hotbar that fades by itself), e.g.
    "Welcome back to Oakvale. All is well."
